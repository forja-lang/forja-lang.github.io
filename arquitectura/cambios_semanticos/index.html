Cambios Semánticos y de Léxico

Forja ha evolucionado significativamente desde sus inicios. Este documento cataloga todos los cambios semánticos y de léxico —traducciones de palabras clave, renombres de constructores, cambios de sintaxis y evolución del sistema de tipos— que han ocurrido durante el desarrollo del lenguaje.

1. Léxico: Palabras Clave Traducidas al Español

Forja es un lenguaje en español. Todas las palabras clave del lenguaje están en español (con algunas excepciones por compatibilidad). El mapeo completo se encuentra en compiler/forja-syntax/src/lexer.rs.

2. Constructores de Option y Resultado

Forja soporta tipos algebraicos Opcion (Option) y Resultado (Result) directamente como variantes del AST (expresiones nativas), sin necesidad de un prelude. Los constructores aceptan tanto su forma en español como su forma en inglés para compatibilidad máxima.

Archivo fuente: compiler/forja-syntax/src/ast.rs, compiler/forja-bytecode/src/opcode.rs

TipoConstructorVariantes aceptadasTag interno
OpcionAlguno(valor)Alguno, Algo, Some"some"
OpcionNinguno()Ninguno, None"none"
ResultadoOk(valor)Ok"ok"
ResultadoError(valor)Error, Err"error"

2.1. Uso en código

Ejemplo: Option y Resultado en Forja
// Las tres formas son equivalentes:
variable a = Alguno(42)
variable b = Algo(42)
variable c = Some(42)

// Pattern matching con constructores en español:
coincidir (a) {
    caso Alguno(v) => escribir("Tengo: ", v)
    caso Ninguno => escribir("No hay valor")
}

// Resultado:
variable res = Ok("exitoso")
variable err = Error("falló")

// También funciona con inglés:
variable res2 = Ok("ok")
variable err2 = Err("error")

2.2. Pattern matching interno

Cuando se usa coincidir con estos constructores, el compilador genera bytecode que inspecciona el campo "tipo" del objeto (vía GetField("tipo")) y lo compara con el tag interno. Si hay subpatrones (ej: Alguno(v)), extrae el campo "valor" y lo asigna a la variable.

Bytecode generado para caso Alguno(v)
Dup
GetField("tipo")
PushTexto("some")
Igual
JumpSiFalso(label_next)
GetField("valor")
Store("v")
[ejecutar cuerpo]
Label(label_next)

Para más detalles sobre este proceso, ver compiler/forja-bytecode/src/opcode.rs y compiler/forja-syntax/src/parser/.

8. Historial de Cambios Semánticos Relevantes

8.1. Eliminación de mut en variables locales

Inicialmente Forja requería mut en toda variable mutable (como Rust). Se simplificó: ahora variable implica mutabilidad por defecto, y constante implica inmutabilidad. mut se conserva solo para parámetros de función y referencias prestadas.

8.2. De String a Texto

El tipo de cadena de caracteres se renombró de String a Texto para mantener coherencia con el idioma español. El cambio fue únicamente de nombre; la representación interna sigue siendo un String de Rust.

8.3. De Bool a Booleano

El tipo booleano se renombró de Bool a Booleano siguiendo la misma filosofía de españolización.

8.4. De None/Some a Ninguno/Alguno

Los constructores de Option se renombraron manteniendo compatibilidad hacia atrás. Actualmente se aceptan: Alguno, Algo, Some para el caso con valor; y Ninguno, None para el caso vacío. Ver sección 2 arriba.

8.5. De interface/trait a rasgo

Originalmente Forja usaba trait (como Rust) e interface (como Java). Se unificó bajo rasgo para mantener el español.

8.6. Adición de Design by Contract

Forja incorporó posteriormente requiere, asegura, siempre, resultado y anterior como keywords para el sistema de contratos (inspirado en Eiffel). Estas palabras no existían en versiones iniciales del lenguaje.

8.7. De println/print a escribir

Las funciones de salida estándar se renombraron de println/print a escribir. Sigue aceptando múltiples argumentos separados por coma.

8.8. Adición del tipo Exacto

Se agregó posteriormente el tipo Exacto para aritmética de precisión arbitraria (basado en (i128, u32) para coeficiente y escala), incluyendo soporte completo en el bytecode (Opcode::SumaExact, Opcode::MulExact, etc.) y en la VM ForjaFast.

8.9. De self/this a este

La palabra clave para referirse a la instancia actual evolucionó de aceptar self (como Rust/Python) y this (como Java/JS) a la forma unificada este en español.
